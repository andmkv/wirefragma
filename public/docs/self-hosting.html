Overview

Operators

Self-hosting

Any static host runs the guest editor. Add PHP and MySQL for accounts, and PHP 8.1 for MCP — ordinary shared hosting is enough.

Static only

npm install
npm run build        # → dist/

Upload the contents of dist/ anywhere (it uses relative paths, so a sub-folder works). Without a configured backend the app starts as the guest editor.

With accounts (PHP + MySQL)

  1. Build with MCP: npm run build:deploy (needs Composer on the build machine), or npm run build without it.
  2. Create a MySQL/MariaDB database and import server/schema.sql.
  3. Copy server/api/config.sample.php to a private place — e.g. /home/USER/wirefragma-config.php, outside public_html — and fill in the database, app_url, mail and privacy settings.
  4. Upload the contents of dist/, including the hidden .htaccess files, and enable HTTPS.
  5. Check /api/index.php?action=status returns "enabled": true, then create an account.

Enabling MCP

  • PHP 8.1 or newer for the site (the accounts API alone still runs on 7.4).
  • In the config file set 'mcp' => ['session_dir' => '/home/USER/.wirefragma-mcp-sessions'] — a private, writable folder outside the web root.
  • The token table is created automatically on first use.
  • Verify: /mcp/composer.json and /mcp/vendor/autoload.php answer 403; /mcp/ without a token answers 401.
  • If a valid token still gets 401, your PHP handler drops the Authorization header; the bundled .htaccess forwards it, or enable CGIPassAuth On.
Keep secrets out of the web root. The config file holds database and mail passwords; the build never copies it into dist/. Never commit it.

MCP configuration options

'mcp' => [
    'enabled'         => true,
    'endpoint'        => '',   // default: app_url + "mcp/"
    'session_dir'     => '/home/USER/.wirefragma-mcp-sessions',
    'allowed_hosts'   => [],   // extra Host/Origin names; app_url's host is always allowed
    'allowed_origins' => [],   // CORS for browsers; keep empty for MCP clients
],

Updating

Rebuild and upload dist/ again; the config file lives outside it and is untouched. schema.sql is safe to re-import. The technical deployment guide in the repository (docs/deployment.md) has the full details.
