Project format & HTTP API

One JSON document per wireframe, used everywhere: in the editor, in exports, in the database and over MCP.

The project document

{
  "version": 2,
  "title": "Sign in",
  "canvas": { "mode": "mobile", "width": 390, "height": 844 },
  "layers": [ { "id": "layer_form", "name": "Form", "visible": true, "locked": false } ],
  "elements": [
    {
      "id": "el_submit", "type": "button", "name": "signInButton",
      "label": "Sign in", "note": "Primary action. Disabled until both fields are filled.",
      "x": 48, "y": 360, "width": 294, "height": 44,
      "layerId": "layer_form", "parentId": "el_card",
      "visible": true, "locked": false, "zIndex": 5
    }
  ]
}
  • Units are logical pixels; origin at the canvas top-left, y grows down; coordinates are absolute, also for nested elements.
  • layers[0] is the front-most layer; within a layer, later elements draw on top. Children follow their parent and use its layer.
  • Optional per-type fields: items, columns, textStyle, contentSize, diagram (Canvas scene), drawing (strokes + description).
  • Unknown fields are preserved by the server; the editor repairs recoverable problems (missing ids, bad layer references, too-small sizes) when it loads a document.

The complete, always-current description — every element type, limits, an example and a JSON Schema — is the WIREFRAGMA schema (Export dialog, or get_wirefragma_schema over MCP).

Account HTTP API

The browser talks to api/index.php?action=<name>. It is a first-party API for the web app: session cookie authentication, and every POST needs the X-CSRF-Token from status. For programmatic access use MCP with a personal token instead.

ActionMethodPurpose
statusGETbackend available, current user, CSRF token, captcha and privacy info
register · verify · resendPOSTsign-up with captcha, email confirmation
login · logout · forgot · resetPOSTsessions and password reset
settings-save · password-change · delete-accountPOSTprofile, preferences, password, account deletion
projectsGETthe project tree: ids, names, wireframe titles and revisions
project-create · -rename · -deletePOSTprojects (delete cascades)
wireframeGETone wireframe with its document (&id=)
wireframe-create · -save · -rename · -duplicate · -deletePOSTsave sends baseRevision; a stale one answers 409 with current
mcp-tokensGETMCP endpoint URL and your tokens (never the secrets)
mcp-token-create · mcp-token-revokePOSTcreate (current password required; the token is returned once) · revoke

Errors are JSON: {"error": "<code>", "message": "…"} with a matching HTTP status.

Revisions

Every wireframe has a revision that increases with each save and rename, whoever made it. Writers send the revision they started from; a mismatch is a conflict, never a silent overwrite. The browser polls the projects tree to notice other writers.
